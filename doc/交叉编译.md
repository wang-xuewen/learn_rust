# 一句话结论
Rust **支持 Windows 编译 Linux 程序**，但**不像 Go 那样开箱即用、零依赖**，Go 自带多平台链接器；Rust 本身编译器支持多 target，但**缺少目标平台的 linker + C 库（glibc/musl）**，这是最大区别。

> Go：`GOOS=linux GOARCH=amd64 go build`，Windows 上直接出 Linux 二进制，纯 Go 代码几乎不用额外东西。
> Rust：`rustc` 可以选 target，但**链接环节是瓶颈**。

## 三种方案（Windows 主机 → Linux 二进制）
### 方案1：纯 musl 静态编译（最简单，推荐纯Rust无C依赖）
musl 是静态 libc，编译出来是**静态单文件，不依赖系统glibc，放任意Linux都能跑**
```powershell
# 1. 安装目标std库
rustup target add x86_64-unknown-linux-musl
# 2. 编译（这里依然缺linker，原生cargo build大概率报错！）
cargo build --target x86_64-unknown-linux-musl --release
```
👉 问题：Windows 没有 `musl-gcc`。
👉 解决工具二选一：
1. **cargo-zigbuild（推荐，不需要Docker！用Zig当linker）**
```powershell
cargo install cargo-zigbuild
cargo zigbuild --target x86_64-unknown-linux-musl --release
```
Zig 自带全平台交叉链接器，Windows 直接跑，非常适合服务端 Rust 项目。

2. **cross（cross-rs，Docker方案，最稳，有C依赖首选）**
```powershell
# 需要先装好 Docker Desktop 并启动
cargo install cross
cross build --target x86_64-unknown-linux-gnu --release
# musl静态版本
cross build --target x86_64-unknown-linux-musl --release
```
cross 在容器内编译，容器里配齐了 Linux gcc、glibc、sysroot；**只要能在Linux本机编译的crate，cross基本都能编译**，包含带 `cc-rs`、openssl 这类C绑定的包，是生产常用方案。

### 方案2：原生手动配MinGW / 独立cross-linker（不推荐新手）
Windows 装 mingw-w64 的 linux cross toolchain，然后在 `.cargo/config.toml` 指定 linker：
```toml
[target.x86_64-unknown-linux-gnu]
linker = "x86_64-linux-gnu-gcc"
```
维护麻烦，glibc版本、sysroot很容易不匹配，经常出现运行时 `version GLIBC_2.xx not found`。

### 方案3：WSL2（折中）
直接在 WSL2 的 Ubuntu 里面 `cargo build`，相当于原生Linux编译，二进制兼容性最好，很多后端开发这么干。

## target triple 对照表（常用）
- `x86_64-unknown-linux-gnu`：动态链接 glibc，适合新版Ubuntu/CentOS，二进制小，但是glibc版本绑定
- `x86_64-unknown-linux-musl`：静态链接，无外部依赖，体积大一点，到处能跑
- `aarch64-unknown-linux-gnu` / `aarch64-unknown-linux-musl`：arm64 Linux（树莓派、云arm实例）

## 和Go的差异总结
1. Go：内置链接器，不依赖主机C工具链，**纯Go代码跨平台一键出包**；
2. Rust：rustc 前端支持多目标，但**链接依赖外部linker + libc**；
   - 纯Rust、无C依赖：`cargo-zigbuild` 体验接近Go；
   - 含 openssl、sqlite、ffmpeg 等C库：必须 `cross`（Docker）或者WSL，否则很难搞定；
3. Rust 的好处：可以选择静态(musl) / 动态(glibc)两种链接模式，粒度更灵活。

## 我的推荐路线（Windows开发Rust服务端）
- 简单工具、无C依赖：**cargo-zigbuild + musl**，不用Docker，一键静态包；
- 带openssl、底层C绑定、生产正式包：**cross + Docker Desktop**；
- 不想折腾：直接WSL2内编译。
