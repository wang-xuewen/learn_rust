“零成本抽象”（Zero-Cost Abstractions）在 Rust 里的核心意思是：**你使用的高级语言特性（如泛型、迭代器、Trait），在编译优化后，不会带来额外的运行时开销（速度或内存上的损失）**。你写的高层代码，性能上可以媲美甚至等同于你亲手写的底层代码。

### 🎯 核心理念来源
这个概念源自 C++ 之父 Bjarne Stroustrup 提出的“零开销原则”：
*   **你不用的东西，你不需要为之付出代价。**
*   **你用的东西，你也不可能手写得更好。**

### ⚙️ Rust 是如何做到的？
Rust 主要依靠**编译期**的机制来“消除”抽象带来的开销：

1.  **静态分发与单态化 (Monomorphization)**：当你使用泛型或 Trait 时，编译器会为每一种具体用到的类型“特化”出一份专门的机器码。原本抽象的调用，在编译后变成了直接的静态调用，没有运行时查找的开销。这与 C++ 的模板类似，但 Rust 的类型检查更早、更严格。
2.  **编译器优化与零大小类型**：一些用于类型安全的“标记”类型（Zero-Sized Types），在编译后会被完全剥离，不占用任何内存。例如，用类型状态模式写的代码，最终可能被优化成一条简单的机器指令。
3.  **迭代器的深度优化**：Rust 的迭代器链（如 `map`、`filter`）通常会被编译器内联、循环展开，并消除不必要的边界检查，最终生成的汇编代码往往和你手写的 `for` 循环一样高效。

### 💡 一个重要的澄清
“零成本”**不等于“零开销”**。它指的是**抽象本身**不强制引入额外的开销（比如动态分发的查表、中间分配），而不是说你写的任何代码都绝对最快。如果你在迭代器里调用了 `clone()` 或者 `collect()` 到一个新 `Vec`，那确实有成本，但这成本来自你的具体操作，而不是“用了迭代器”这个抽象本身。另外，这些优化通常在 `--release` 模式下才生效，Debug 模式下性能对比没有意义。
